# Phase 6C. Визуальный редактор DataTemplate

## Исходное состояние

Исходная ревизия — `96c88c2`, ветка `main`. При начале работы дерево было чистым. В рабочей копии, истории отчётов и прежних артефактах Phase 6C отсутствовала. Отчёт Phase 6B содержит результат 44/44. В исходном коде уже существовали однополевый `ListBox.ItemTemplate.DisplayField`, редактор коллекций и специализированные шаблоны колонок DataGrid.

## Как пользоваться редактором

1. Выбрать ListBox, ComboBox или ItemsControl в форме JSON Designer и нажать **ItemTemplate** в Inspector.
2. Добавить элементы через Toolbox. Корневой Grid шаблона поддерживает вложенные контейнеры. Свойства, порядок дочерних элементов и выражения редактируются через обычные Explorer и PropertyGrid.
3. Для привязки к объекту коллекции выбрать строку свойства и открыть **fx**. Например, для `TextBlock.Text` указать `{Binding Title}`. Путь **ItemsSource** в заголовке редактора задаётся относительно владельца коллекции. Для существующих локальных данных его можно оставить пустым.
4. **Предпросмотр** позволяет выбрать 0, 1 или 3 примера и тему Light или Dark. Образцы содержат `Title`, `IsChecked` и `Thumbnail`. Длинный заголовок входит в третий пример. Они существуют только в окне просмотра.
5. **Применить** записывает шаблон в выбранную форму. **Отмена** закрывает черновик. **Удалить шаблон** снимает локальный визуальный ItemTemplate. После выхода выделенным остаётся владелец.

Проверка UI нажимает реальную кнопку ItemTemplate, подтверждает перемещение прежнего экземпляра DesignerSurface, выбирает вложенный TextBlock и применяет черновик. Добавление вложенных узлов в автоматическом сценарии выполнено командами модели. Перетаскивание физической мышью при разных DPI остаётся отдельной проверкой.

## Архитектура и границы поддержки

| Объект | Возможности Phase 6C |
|---|---|
| ListBox, ComboBox, ItemsControl | Создание, замена и удаление ItemTemplate. Локальные строки и обычный путь ItemsSource. Для ListBox используется также существующий BindingSource. |
| TextBlock, Image, Border, StackPanel, Grid, DockPanel, WrapPanel, Button, CheckBox | Вложенные элементы шаблона. DockPanel использует существующий дескриптор Group с режимом Dock. При генерации проверяется наличие нативного элемента для каждого дочернего узла. |
| ContentTemplate и HeaderTemplate | Исходная разметка сохраняется. Визуальный режим относится к ItemTemplate. |
| TreeDataTemplate, DataGridTemplateColumn | Остаются в своих существующих сценариях. Произвольные иерархические данные и пользовательские шаблоны колонок требуют отдельной приёмки. |
| ControlTemplate, TemplateBinding, CompiledBinding, x:DataType | Исходная разметка защищена. При неизвестном типе строки генератор использует обычный Binding. |

Окно временно перемещает существующие экземпляры DesignerSurface, Toolbox, дерева Explorer и PropertyGrid в область шаблона. Черновик использует обычный MainWindowViewModel, реестр и DesignerDocumentSession. В окне формы сохраняются её DocumentId, владелец, выделение и ревизия. Отложенный контекстный запрос сбрасывается на переходе между режимами. Глобальные настройки берутся из формы, автосохранение пропускает открытый черновик.

Операции внутри черновика используют обычную историю дизайнера. Применение или удаление шаблона создаёт одну операцию в истории формы. Применение проверяет владельца и активный документ. Кнопка в окне дополнительно проверяет ревизию формы. При выходе снимаются обработчики, останавливаются таймеры и освобождаются сессии черновика.

## Данные, ресурсы и сериализация

Необязательное поле `DesignerControlFileModel.ItemTemplate` версии 1 хранит строки и колонки корневого Grid, путь коллекции и обычные DTO дочерних компонентов. Порядок, ParentId, локальные значения и выражения остаются в существующих полях. Старые проекты без ItemTemplate загружаются прежним путём. Копирование компонента копирует дерево шаблона. При загрузке проверяются версия, типы, идентификаторы, вложенность, циклы и единственный ребёнок Border.

Путь коллекции и привязки отдельных свойств проходят через валидатор Phase 6A. Например, у владельца `ItemsSource="{Binding Orders}"`, внутри шаблона `Text="{Binding Title}"`. Образец в сгенерированном приложении получает реальный тестовый DataContext только от runtime probe. До назначения данных коллекция пуста. Редактор сохраняет выражение, в том числе для `Image.Source`. Конвертеры пользовательских типов в авторском подмножестве исключены.

Именованные ресурсы и объявления стилей формы поступают из Phase 6B. В AXAML приложения разрешение выполняет Avalonia. Нативная проекция черновика получает проверенные ресурсы и стили. Динамическая кисть сохраняет ссылку при смене темы. У локальных записей проверяются имя контейнера, IsEnabled, вложенность, Content и дополнительные поля. Настройки, которые потерялись бы при переходе к строкам коллекции, блокируют применение.

## JSON, AXAML и Preview

JSON проверялся через сохранение workspace и загрузку в новый экземпляр Designer. Экспорт шаблона использует существующие дескрипторы компонентов, построение layout и генерацию выражений. Внутренние имена принадлежат области шаблона. Обычные выражения формы не захватывают одноимённый узел внутри DataTemplate. AXAML Preview и скомпилированное приложение используют DataTemplate из сгенерированной разметки. Legacy Preview и Designer получают нативный IDataTemplate. Кэш нативной фабрики привязан слабым ключом к снимку шаблона.

Для импортированного AXAML редактирование привязано к уже имеющемуся диапазону значения атрибута. Поддерживается прямой ItemTemplate однозначно именованного владельца в Window с одним простым DataTemplate. Диалог показывает путь вложенного компонента, свойство и значение. Операция обновляет существующую карту значений документа и проходит через обычный writer, историю и проверки версии и checksum. Смена `{Binding Title}` на `{Binding Caption}` проверена сравнением всего исходного текста, включая комментарий, кавычки и соседний атрибут. Undo восстанавливает исходный текст.

Нативная проекция импорта строится из разрешённых типов и проверенных атрибутов. Структурное редактирование импортированного шаблона закрыто. Для Reset в данном диалоге доступно восстановление исходного **значения** атрибута. Удаление исходного атрибута с последующей точной обратной вставкой после ACK в этот контракт не входит. Префиксы, необычные значения, неподдерживаемые шаблоны и неизвестные атрибуты остаются в исходном файле. Импорт и редактирование значения имеют более широкую область применения, чем нативное воспроизведение всего шаблона.

## Проверки запущенного приложения

Для Grid и Canvas независимо создан workspace, сохранён JSON, проект повторно открыт, экспортирован, собран и запущен. Probe проверяет материализованное визуальное дерево каждого типа владельца. Проверяются текущая строка в DataContext, показанный текст, FontSize из StaticResource, кисть из DynamicResource при Light и Dark, пустая коллекция до назначения данных, Orders/Title после назначения, девять нативных типов и объект изображения из текущей строки. Дополнительные проверки читают значение Opacity из именованного селектора, текст из соседнего компонента через ElementName и собственное имя через RelativeSource Self. Тестовый DataContext подключает сам probe после запуска приложения.

## Первые неуспешные прогоны

- Исходный набор 6C дал 1/3. Загрузчик XamlX отклонил повторное объявление namespace на property element. Также проверка дочерних типов отклонила служебный Canvas, созданный экспортёром Border. Удалено дублирование namespace при сериализации. Служебный Canvas разрешён в проверенном результате генерации.
- Решение однажды не собралось с MSB3027 и MSB3021. Копируемый EremexDesignerPlugin.dll удерживал .NET host PID 5076 во время тестов. Первый лог сохранён. Регрессионный runner также однажды не скомпилировался из-за обращения тестов к internal API. Проверки переведены на пользовательскую кнопку и публичные команды.
- Первая расширенная сцена с изображением завершилась управляемой ошибкой `Expression export target is ambiguous: RowImage`. Отдельный прогон с выводом исключения установил место потери дочернего дерева. В качестве родителя передавался тип DockPanel, тогда как обычный Designer экспортирует DockPanel через Group и режим Dock. После исправления оба runtime probe проверяют каждый ожидаемый нативный тип и значение Image.Source.

- После добавления проверки истории получилось 10/11. Порядок изменялся правильно, но быстрый Reorder попадал в то же 500-миллисекундное окно группировки Undo, что и создание дочернего элемента. Для структурных команд черновика использована существующая отдельная транзакция Grid Editor. Тест выполняет реальные команды перемещения и удаления, затем проверяет порядок, идентификаторы и ParentId после Undo/Redo.

- В дополнительной проверке экспортированный TextBlock получал текст соседнего элемента через ElementName, но собственное имя через RelativeSource Self при загрузке оставалось пустым. При замене x:Name на Name генератор помещал имя после привязки. Контрольная копия того же проекта прошла проверку при перемещении одного атрибута. Генератор теперь устанавливает Name перед привязками. Сохранены исходное наблюдение и два контрольных варианта в `post-history/scope-check`.
- В промежуточных и финальном прогонах Broad все 72 сценария прошли. При последующей очистке временного каталога возник UnauthorizedAccessException для ToolboxStandardItemsExport.dll. Временные файлы этой сессии сохранились. Журнал финального запуска содержит оба результата.

Исходные журналы находятся в `artifacts/universal-phase6c/first`, `matrix2`, `final` и `release-6c/6c-history.log`. Старые файлы результатов сохранялись отдельно от последующих прогонов.

## Ограничения и следующий этап

- Native UIA crash — **UNRESOLVED**. Причина исторического Legacy_CancelledOwnerClose по-прежнему неизвестна.
- Installed VSIX и физический DPI/DnD — **NOT VERIFIED**. Интеграция с буфером VS использует существующую схему ACK. Автоматический IPC проверяется отдельно.
- Визуальный редактор работает с одним корневым Grid и ограниченным набором стандартных дочерних типов. Собственные контейнеры элементов с метаданными требуют отдельного адаптера. Ресурсы приложения или внешней сборки должны присутствовать в целевом проекте.
- Следующий этап может расширить source mapping на безымянных владельцев и обратимое удаление атрибутов, проверить типизированные строки с x:DataType, иерархические данные и DataGridTemplateColumn. Для Inspector и больших документов сохраняется отдельная задача измерения задержек.
