# Phase 6B. Визуальное редактирование стилей и ресурсов

18 ноября 2026 года. Исходная ревизия `18f1a72`, Avalonia 11.1.1, Release, Windows. Исходные контракты и ограничения сверены с отчётами Phase 3A, 3B, 4A, 4C, 5G и 6A.

При повторной приёмке за основу взят коммит `f421937` с редактором Phase 6B. Доработаны фильтр типов ресурсов, поиск по области «Общий» и пояснения для защищённых записей AXAML. В набор Phase 6B добавлены проверки фильтра ресурсов, объяснений при импорте и освобождения Legacy Preview при активном таймере полосы прокрутки DataGrid.

**STYLES & RESOURCES: READY WITH CONDITIONS.** Phase 6B прошла 44/44. Стили для пяти целевых типов и восемь видов ресурсов проверены в запущенных приложениях Grid и Canvas. После исправления таймера DataGrid в закрытом Legacy Preview три независимых процесса прошли 36/36 каждый. Сохраняются ограничения редактирования импортированных объявлений, риск P95 Inspector и условия ручной приёмки VSIX и DPI.

## Что доступно пользователю

В панели свойств откройте «Стили и ресурсы». Для примера выберите Button, создайте стиль `Button.primary`, добавьте Setter для CornerRadius и назначьте класс выбранной кнопке. Если на кнопке есть собственный CornerRadius, действие «Взять свойство из стиля» снимает локальное значение. Сохраните проект и откройте Preview. На вкладке ресурсов можно создать кисти с одинаковым ключом в отдельных темах Light и Dark, затем выбрать DynamicResource для Background этого стиля.

При открытии существующего AXAML редактор показывает исходные значения с доступным точечным изменением и список объявлений, доступных для чтения. После изменения скаляра в VsHost используется обычная команда применения в буфер Visual Studio. ACK подтверждает применение правки к текстовому буферу. Файл на диске обновляет команда Save в Visual Studio.

### Селекторы и свойства

Первая группа целевых типов включает Button, TextBox, TextBlock, Border и CheckBox. Поддерживаются тип, `Тип.класс`, `Тип#имя` и ввод `#имя` при выбранном типе. В генерируемом AXAML последний записывается как `Тип#имя`, чтобы XamlX знал владельца типизированного Setter. Для импортированного именованного селектора проверяется однозначность целевого элемента. Редактирование существующего сложного селектора закрыто целиком при любой неподдерживаемой части. [Синтаксис селекторов Avalonia](https://docs.avaloniaui.net/docs/styling/style-selector-syntax)

В проверенный набор вошли Background, Foreground, BorderBrush, BorderThickness, CornerRadius, FontSize, FontWeight, Padding, Margin, Opacity, HorizontalAlignment, VerticalAlignment, MinWidth, MinHeight, FontFamily, LetterSpacing и FontStyle. Конкретный тип получает пересечение с его доступными для записи styled properties в существующем Metadata Engine. Проверяются тип значения и валидатор свойства. Binding в Setter требует отдельной проверки семантики контекста целевого элемента. Безопасный Binding Editor Phase 6A для локальных значений продолжает работать.

### Ресурсы и область видимости

Вкладка «Ресурсы» сочетает фильтр «Все типы» с поиском. Например, выбор Color и поиск «Общий» показывают только цвета общей области формы. Если выбранная запись остаётся в списке, сохраняются выделение и введённое значение. Одинаковый ключ в другом варианте темы считается другой записью.

При импорте редактор объясняет, почему запись доступна для чтения. В частности, он показывает ключ ресурса с комментарием или другой XML-разметкой внутри текста, самозакрывающийся элемент без диапазона значения, а также неизвестный или повторяющийся тематический словарь. Простое значение рядом с ними можно изменить одним patch.

Восемь видов значений имеют явный разбор — Color, SolidColorBrush, Thickness, CornerRadius, Double, String, локальный FontFamily и именованный FontWeight. Для чисел отсеиваются нечисловые и бесконечные значения. Проверяются корректность XML, совместимость ресурса с типом Setter, ключи в одной области и конфликты со служебной палитрой. Ссылки между документами при переименовании требуют проверки пользователем. Редактор выводит предупреждение. Оставшаяся ссылка из редактируемого Setter той же формы блокирует некорректную транзакцию.

StaticResource в авторском Setter требует ресурса совместимого типа в общей области. Для DynamicResource поддерживаются тематические варианты. Один ключ разрешён в разных вариантах, дубликат внутри варианта отклоняется. Список ключей Phase 6A дополнен записями текущей формы. Значения не вычисляются путём загрузки неизвестной DLL, исполнения пользовательского AXAML или создания произвольного объекта через Reflection. [Варианты темы Avalonia](https://docs.avaloniaui.net/docs/styling/theme-variants)

## Интеграция, хранение и история

- Одна команда в существующем Inspector открывает диалог по запросу. Строки Inspector используют прежние категории, избранное и поиск. Редактор Setter использует metadata целевого типа и существующие текстовый и составной редакторы, для enum доступен выбор допустимых значений. Изменения вводятся в локальную черновую строку, затем проходит проверка всего изменённого набора.
- Существующая поверхность обновляется через DesignerChanged. Сохранение Setter не требует отдельного вызова построения PropertyGrid. В оконном тесте выделенный ControlId сохранился после изменения и Undo. Положение прокрутки при ручном использовании установленного VSIX отдельно не измерялось.
- Опциональное поле формы `Appearance` версии 1 хранит списки стилей, Setter, ресурсов и назначенные классам ControlId. JSON не содержит объектов Avalonia. Старый проект без поля открывается и сохраняется без принудительного добавления раздела. Неизвестная версия и повреждённая структура проверяются до замены рабочего проекта.
- Каждая операция с листом оформления использует одну транзакцию существующей истории. При отказе валидации предыдущая модель остаётся доступной. Для локального сброса удаляют Setter или снимают локальное значение, чтобы применился стиль. Общие Undo/Redo доступны после закрытия диалога. Проверка активной формы и ревизии защищает от устаревшего черновика.
- В импортированном документе ленивый каталог опирается на существующее дерево синтаксиса и source spans. Сохранение значения использует тот же patch writer, проверку пересечений, версию/checksum и ACK. Полная регенерация импортированного файла не вызывается. Изменения внутри чужой XML-области, сложного Setter или неоднозначного ключа блокируются. Принимается только поле актуального каталога.
- Для Undo после ACK важна исходная запись XML. Редактор предлагает замену лишь тогда, когда исходная лексема может быть точно восстановлена. Числовые XML-ссылки и альтернативное экранирование защищены от неявной нормализации.
- Проверки сравнивают полный исходный текст с заменой одного диапазона, затем Undo/Redo после ACK. В fixture присутствуют комментарий, одинарные кавычки, чужой namespace и атрибут, Binding, DynamicResource, ControlTheme и DataTemplate. Проверены обычный Setter, кисть Window и кисть Dark.
- При генерации документа объявления дополняют существующие Window.Resources и Window.Styles. Предварительная проверка проходит для всех экспортируемых форм. У проекта сохраняется обычная публикация Folder/ZIP. В импортированном AXAML структурное создание и удаление Style, Setter и ресурса, правка селектора и переименование ключа закрыты. Доступны точечные изменения уже существующих простых значений.

## Отображение и экспорт

У авторских проектов сохраняются локальные значения и приоритет Avalonia. Для Designer, Legacy Preview и безопасного импортированного Preview используется проверенный набор native Style/Setter. AXAML Preview авторского проекта и сгенерированный проект получают объявления через штатную генерацию. Прозрачность, размеры и цвета не имитируются отдельным layout engine.

Проекты Grid и Canvas были сохранены в JSON, повторно открыты, экспортированы, собраны и запущены. В каждом процессе проверены фактические Button и TextBox. Для Button проверены класс `primary`, CornerRadius = 9 и Background при Light и Dark. Для TextBox проверен FontSize = 23 через StaticResource. Все восемь типов ресурсов проверены через значение в нативном словаре или свойство контрола. Логи двух приложений находятся в `artifacts/universal-phase6b/reviewed-generated/`.

Дополнительный экспорт подтвердил для Grid и Canvas вложенные TextBlock, CheckBox и Border. В запущенных приложениях внутри настоящего StackPanel у каждого элемента был ожидаемый тип и Opacity = 0,64. Вместе с Button и TextBox это покрывает все пять доступных целей редактора. Обобщать проверку на каждую комбинацию свойства и типа нельзя. В экспортированном дереве часть контейнеров оформлена внешним Border. Селектор по типу Border может совпасть и с таким обрамлением. Для адресного стиля подходят имя или класс. В безопасной проекции Designer стили сопоставляются с элементами модели. Логи находятся в `artifacts/universal-phase6b/all-targets-verified/`.

До подтверждённого закрытия сохраняется интерактивное поведение окна. Модель формы, COM и глобальные настройки Dispatcher при этом не меняются.

### Первые отказы

1. Первый прогон Phase 6B дал 23/24. Legacy Preview показал ожидаемые Setter, AXAML Preview не создал ожидаемую кнопку. Первая сборка экспортированного Grid сообщила AVLN2200 о неизвестном типе цели Setter в стиле `#SaveButton`. После генерации `Button#SaveButton` обе проекции и оба приложения прошли эту проверку. 3. После успешных 72/72 Broad сообщил об отказе очистки временной DLL `ToolboxStandardItemsExport.dll`. Выход тестового процесса 0. В каждой из двух последних серий Broad по три сообщения об отказе очистки временных файлов — два для `ToolboxStandardItemsExport.dll` и одно для `CommunityToolkit.Mvvm.dll`. Результаты сценариев и оставшиеся файлы сохранены в соответствующем каталоге прогона.

В сгенерированном AXAML имя принадлежит внешнему Border, а его Child — стандартный StackPanel. Проба исправлена по фактической структуре и по-прежнему проверяет тип родителя, наличие всех трёх дочерних типов и значение их native Opacity. Код экспорта для этого случая не менялся.
